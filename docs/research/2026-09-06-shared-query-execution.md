# Shared query execution and shell lifetime

Date: 2026-09-06. Stage: M2 after approval of direction A. The user explicitly clarified that
compatibility preserves observable behavior while replacing the underlying mechanism; it must
not keep old and new collection executors in parallel.

## Implementation

The finite PostgreSQL frontend uses the pinned parser selected at M1. SQL is parsed in a worker,
positively validated, and lowered to a typed query. Commands build the same logical selections
without generating SQL strings. `canonical` owns public row projection, predicates, ordering,
paging, and usage; `live-runtime` prepares sources and exposes one collection execution entry.

The CLI, human shell, and v2 latest/list operations now call the shared template and executor.
Their old session/turn filtering and pagination branches were removed. The source-bounded
`sample` preview also uses the latest selection after its existing source preparation. Input
syntax and output envelopes remain distinct boundary adapters, not separate history semantics.
Ranked search, project/family views, detail, and stats continue to use their existing canonical
services; no SQL implementation of those operations was added.

The new entries are `query --sql`, `--sql-file`, positional JSON parameters, v3 SQL request files,
and one-line SQL in the existing shell. New SQL results include selected columns, explicit nulls,
read identity, and coverage. Default total is null; requesting complete execution exposes the
exact matching total. At the M2 checkpoint, execution always prepared the complete selected scope.
The subsequent selective latest implementation is recorded separately in the
[M3 report](2026-09-06-selective-latest.md); this report makes no avoided-source-read claim.

A shell publishes a snapshot only after successful preparation, reuses it for collection reads,
and retains the previous one after refresh failure. Default idle expiry is 300 seconds, zero
disables it, input activity resets it, and active work/pending output suspends it. Exit/EOF/expiry
release ownership. Parser workers terminate after compilation; they do not retain history.

The artifact builder now copies the resolved external dependency closure, including license files,
and includes it among bundled dependencies. SQL executes from both the extracted standalone
artifact and a local npm installation of its packed package. No database engine or history store
was added. No native history was read for this implementation validation.
